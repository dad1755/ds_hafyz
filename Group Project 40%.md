# GROUP ASSIGNMENT – 40%

**Project Title:** Development of a Machine Learning Predictive System in a Selected Sector

## Assessment Distribution

- Project Report: 20%
- Presentation & System Demonstration: 20%
- **Total: 40%**

## 1. Project Overview

Students are required to work in groups to design, develop, test, and demonstrate a machine-learning-based predictive system within a selected sector.

The project may be developed in areas such as:

- Healthcare
- Finance
- Education
- Retail
- Agriculture
- Transportation
- Cybersecurity
- Human Resources
- Manufacturing
- Business Analytics
- Other suitable sectors

The developed system must use a suitable dataset to train and test a machine-learning model and allow users to submit relevant input data to generate a prediction.

The system should demonstrate the integration of:

- Data collection
- Data preprocessing
- Exploratory data analysis
- Machine learning
- Model evaluation
- System development
- User-interface development
- Prediction output
- Recommendations
- System testing

## 2. Project Objective

The objective of this project is to develop a functional predictive system capable of producing meaningful predictions based on user-provided information.

The system should:

1. Use an appropriate real-world dataset.
2. Perform appropriate data preprocessing.
3. Apply machine-learning classification techniques.
4. Support either binary or multi-class classification.
5. Include separate Admin and User roles.
6. Provide an appropriate interface for user input.
7. Generate prediction results.
8. Display probability or confidence values where applicable.
9. Provide meaningful recommendations based on the prediction.
10. Evaluate the predictive model using suitable performance metrics.
11. Demonstrate the complete system through a working prototype.

## 3. Selection of Sector and Prediction Problem

Each group should identify a meaningful prediction problem.

Examples include:

**Healthcare**

- Diabetes prediction
- Heart disease prediction
- Cancer prediction
- Kidney disease prediction

**Finance**

- Loan default prediction
- Credit-risk prediction
- Fraud detection

**Education**

- Student performance prediction
- Student dropout prediction

**Business**

- Customer churn prediction
- Customer purchasing behaviour
- Sales-category prediction

**Cybersecurity**

- Intrusion detection
- Malicious activity classification
- Spam detection

Students should clearly explain the selected problem and why predictive analytics is suitable for addressing it.

## 4. Dataset Collection

Each group must identify and use a suitable dataset.

Datasets should preferably be obtained from reputable sources such as:

- Kaggle
- UCI Machine Learning Repository
- Government open-data portals
- Research repositories
- Recognised institutional datasets

The dataset must be properly referenced.

Students should explain:

- Dataset source
- Number of records
- Number of attributes
- Feature variables
- Target variable
- Type of data
- Class distribution
- Relevance of the dataset to the selected problem

Students should also consider data privacy, ethical use of data, and potential dataset bias.

## 5. Data Preprocessing

Students should prepare the dataset appropriately before machine-learning model development.

The preprocessing stage may include:

- Identification of missing values
- Treatment of missing values
- Removal of duplicate records
- Removal of irrelevant attributes
- Correction of inappropriate data types
- Encoding categorical variables
- Feature scaling
- Normalisation
- Outlier treatment
- Class imbalance handling

The group must explain and justify important preprocessing decisions.

## 6. Exploratory Data Analysis

Students should conduct exploratory data analysis to understand the characteristics of the dataset.

Appropriate analysis may include:

- Descriptive statistics
- Data distributions
- Frequency analysis
- Correlation analysis
- Histograms
- Bar charts
- Boxplots
- Scatter plots
- Heatmaps
- Class distributions

All important visualisations must include meaningful interpretation.

Students should explain what the results reveal about the selected prediction problem.

## 7. Classification Approach

The system must implement either:

### Binary Classification

Binary classification predicts one of two outcomes.

Examples:

- Disease / No Disease
- Fraud / Non-Fraud
- Pass / Fail
- Churn / No Churn

**OR**

### Multi-Class Classification

Multi-class classification predicts one outcome from more than two possible categories.

Examples:

- Low Risk / Medium Risk / High Risk
- Cancer / Diabetes / Heart Disease
- Category A / Category B / Category C

The group should justify the classification approach selected.

## 8. Machine Learning Model Development

Students must develop a machine-learning model appropriate for the selected problem.

Examples of suitable algorithms include:

- Logistic Regression
- Decision Tree
- Random Forest
- Support Vector Machine
- K-Nearest Neighbours
- Naïve Bayes
- Gradient Boosting
- Other appropriate classification algorithms

Students are encouraged to compare multiple machine-learning models before identifying the best-performing model.

The report should explain:

- Selected input features
- Target variable
- Training dataset
- Testing dataset
- Train-test split
- Selected algorithm
- Model parameters
- Training process

## 9. Model Testing and Evaluation

The model must be evaluated using an independent testing dataset.

Appropriate evaluation metrics should be applied, including:

- Accuracy
- Precision
- Recall
- F1-Score

Additional metrics may include:

- Confusion Matrix
- ROC Curve
- AUC Score
- Sensitivity
- Specificity

Where multiple models are used, students should compare them.

Example:

| Model   | Accuracy | Precision | Recall | F1-Score |
| ------- | -------- | --------- | ------ | -------- |
| Model 1 |          |           |        |          |
| Model 2 |          |           |        |          |
| Model 3 |          |           |        |          |

Students should identify the best-performing model and justify why it was selected for final system implementation.

## 10. Predictive System Development

The predictive model must be incorporated into a functional system.

The system should demonstrate the following workflow:

**User Input → Data Processing → Machine Learning Model → Prediction → Result → Recommendation**

A machine-learning notebook alone is not considered a complete system.

## 11. System Roles

The system must contain at least two user roles.

### 11.1 Administrator

The Administrator should be able to perform suitable administrative functions such as:

- Add users
- Edit users
- Delete users
- Manage user roles
- Manage user access
- Upload datasets
- Update datasets
- Manage training/testing datasets
- Configure system settings
- Configure relevant model parameters

### 11.2 User

The User should be able to:

- Access the system
- Enter required input attributes
- Submit information for prediction
- View prediction results
- View prediction probability/confidence where appropriate
- Receive appropriate recommendations

## 12. User Interface

The system should provide a clear and user-friendly interface.

### Admin Interface

The Admin interface should include suitable functions for:

- User management
- Dataset management
- System configuration
- Model-related configuration where applicable

### User Interface

The User interface should contain:

- Input form
- Prediction button/function
- Prediction outcome
- Probability/confidence score where relevant
- Interpretation
- Recommendation

## 13. Recommendations

The predictive system should provide meaningful recommendations based on the predicted outcome.

For example, in a healthcare-based system, recommendations may advise the user to consider consulting a healthcare professional.

The prediction system should not present itself as a replacement for professional medical diagnosis.

## 14. System Testing

Groups must demonstrate that the developed system functions correctly.

Testing should cover areas such as:

- Login/access
- User input
- Input validation
- Prediction generation
- Output accuracy
- Admin functions
- User functions
- Dataset functionality
- Error handling
- System usability

## 15. Challenges and Solutions

The report should identify key problems encountered during the project.

Examples include:

- Missing data
- Dataset imbalance
- Low prediction accuracy
- Model overfitting
- Model underfitting
- Dataset bias
- System integration problems
- Interface issues
- Limited dataset size

Students should explain how these challenges were addressed.

## 16. Ethical and Privacy Considerations

Students should discuss relevant ethical issues including:

- Data privacy
- Data confidentiality
- Dataset bias
- Fairness
- Responsible use of prediction
- Limitations of machine-learning predictions

## 17. Future Enhancements

Students should recommend realistic improvements to the developed system.

Possible improvements include:

- Real-time data collection
- Larger datasets
- Additional features
- Improved machine-learning models
- Explainable AI
- Cloud deployment
- Mobile application development
- Automated model retraining
- Improved interface design
- Continuous performance monitoring

## Important Instructions

- The assignment must be completed as a group project.
- A functional predictive system must be demonstrated.
- A Jupyter Notebook alone will not be considered a complete system.
- The system must contain both Admin and User functionality.
- The prediction model must be properly trained and tested.
- Appropriate machine-learning evaluation metrics must be used.
- All datasets and external sources must be referenced.
- Every group member must understand the project.
- During presentation, the lecturer may direct individual technical questions to any group member.
- Marks may be differentiated between members if there is clear evidence of unequal contribution or inability to explain the submitted work.
- University academic-integrity requirements apply.
