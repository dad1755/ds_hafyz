**Judgement: a pre-existing S1 record defect carried as an operator item — NOT an S4 blocker.**
The reasoning, in the order that decides it:

1. **It predates S4 and S4 does not touch it.** The two values enter tracked history at `3f6f27f`
   ("S1 gate: independent acceptance record"), and `git show 7ab66ce:docs/acceptance/S01.md`
   already contains both. S4's whole diff is `git diff --name-only 7ab66ce..HEAD`, which does not
   include `docs/acceptance/` at all.
2. **S4's own commits introduce no secret.** Scanning the S4 diff for the actual values (loaded
   from the operator `.env`, never printed) finds neither password and not `APP_SESSION_SECRET`.
   The two S4 lines that mention those names are `evidence/s4/check_no_secrets.txt` naming the
   finding, not quoting the value.
3. **No S4 acceptance clause is about it.** The RIDEGAMI-802 clause is about reproduced numbers,
   matrix totals, arithmetic, placeholders and honest recall — all of which pass. Holding S4 open
   for a credential quoted in an S1 record would block a sprint on a defect it cannot fix without
   editing another sprint's acceptance record, which the guardrails forbid.
4. **It is nonetheless a real release risk and is not being waved away.** The repository has no
   remote, so the exposure is local to this host — but the values are in git history, so redaction
   alone does not undo it. **Required before the S13 deployment:** rotate
   `INITIAL_ADMIN_PASSWORD` and `INITIAL_USER_PASSWORD`, then redact the quoting lines in
   `docs/acceptance/S01.md`. This gate did not print the values, did not edit the S1 record, and
   did not rewrite history.
5. **Additional exposure the checker cannot see.** The untracked, git-ignored `PROJECT_DETAILS.md`
   in the working tree also contains both values in plaintext. It is not in git and never was, so
   it is outside the checker's scope and outside the repository, but the rotation item should treat
   it as a second place to update. No action is required for S4.

This is the same finding S2 recorded as F-1 and S3 as F-4, still open. It is now three sprints old;
the operator item should be scheduled before S13 rather than carried again.

## Findings
