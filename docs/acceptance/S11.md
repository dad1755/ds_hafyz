## §5 Two adversarial claims, audited at the code site

**RBAC denial — is the sweep really "every privileged function"?** The test asserts
`denied_after - denied_before == len(PRIVILEGED_CALLS)` and guards that the list is ≥ 14 entries. That
only means something if the list is complete, so I enumerated the surface myself:

```
$ grep -n "^def " src/accounts.py src/data_manager.py      # 14 functions taking a token
$ grep -n "_admin(conn" src/accounts.py src/data_manager.py
accounts.py:124,135,147,163,213,253,298,334   (8)
data_manager.py:358,369,378,453,482,575       (6)
```

14 token-taking functions, 14 `_admin(...)` call sites, and 14 entries in `PRIVILEGED_CALLS` — the two
sets are identical, so no privileged function escapes the sweep. The only other public callables,
`deployed_model_facts` and `ensure_seed_version`, take no session token and expose no account or dataset
data. The claim holds.

**Upload quarantine — is the name really generated and the file really owner-only?** At
`src/validation.py:534-579`: the stored name is `f"{UTC stamp}-{uuid4().hex[:12]}.csv"` and the uploaded
name is never used to build a path; the resolved parent is asserted equal to the quarantine directory; the
write uses `os.open(..., O_CREAT|O_EXCL|O_NOFOLLOW, 0o600)`, so a planted symlink or an existing file
cannot be overwritten or followed. The test's five hostile names (`../../etc/passwd`, a Windows traversal,
`/etc/shadow`, `....//`, a NUL byte) each assert `stored.path.parent == quarantine.resolve()` and mode
`0o600`. The behaviour is what the row says it is.
