and on submit emits one `st.warning`. There is no branch that sets a session flag, logs, or reports

The card's requirement ("must state plainly that nothing was checked and the input was discarded") is
met, and the claim is literally true in a browser: the fields are cleared on submit and nothing

**Evidence-method note (OBS-3):** under AppTest the typed values *remain* in session state after

does not model, so an AppTest-only reading cannot evidence "discarded immediately" — only the browser
run can. The sprint's `evidence/s1/apptest.txt` does not overclaim (it reports no values), but any
later sprint asserting "cleared" must do it in a browser.

## UNVERIFIED

Named explicitly, not assumed:

1. **The live Cloudflare route.** That `www.aihubcampus.online` and `aihubcampus.online` really resolve
   through the tunnel to `http://web:2026` is operator-reported (RIDEGAMI-798, `PROJECT_DETAILS.md`)
   and **not independently verifiable from this host** — the tunnel is remotely managed, `~/.cloudflared`
   is empty, and inspecting it needs Cloudflare API credentials. What *is* proven here: the app answers
   200 and serves a working session for both `Host` names on the internal network. S13 must confirm the
   route against the live domain.
2. **Tunnel token validity / `cloudflared` connectivity.** Never read, never started. S13.
3. **Public HTTPS, DNS, firewall behaviour.** Out of scope for S1; nothing was exposed.
4. **Byte-identical reproducibility of the image across hosts.** The base image is pulled by tag
   `python:3.12-slim`, not by digest (OBS-4), so two builds on different days can differ at the base
   layer. The dependency set itself is fully pinned and verified (§5).
5. **Rollback readiness.** S1 has no data to roll back; the volume is empty and the previous image can
   be rebuilt from the same commit. A real backup/restore drill is S12.
