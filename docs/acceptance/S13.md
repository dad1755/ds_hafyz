## §2 No public origin port

```
$ docker ps --format '{{.Names}}\t{{.Ports}}\t{{.Status}}'
aihubcampus-web-1	2026/tcp	Up 38 minutes (healthy)
aihubcampus-cloudflared-1		Up 2 hours

$ docker inspect -f 'PortBindings={{json .HostConfig.PortBindings}} NetworkPorts={{json .NetworkSettings.Ports}}' ...
aihubcampus-web-1        PortBindings={} NetworkPorts={"2026/tcp":null}
aihubcampus-cloudflared-1 PortBindings={} NetworkPorts={}
```

`2026/tcp` in the `docker ps` PORTS column is an *exposed* port with no host binding —
`NetworkSettings.Ports` maps it to `null`, i.e. reachable only inside `aihubcampus_internal`.
`compose.yaml` declares `expose:` exactly once (`2026`) and `ports:` zero times.

## §3 The ingress is the pre-existing tunnel

- `compose.yaml:71-81`: the `cloudflared` service runs `tunnel --no-autoupdate run` with
  `env_file: {path: .env.cloudflared, required: false}` — no `--config`, no `--url`, no published
  port. The container's environment holds `TUNNEL_TOKEN` (checked by key name only; the value was
  never printed).
- The running tunnel logs 90 requests with `originService=http://web:2026`, which is the in-network
  target the clause requires, observed rather than read off a config file.
- No `cloudflared tunnel route`, `tunnel dns`, or DNS-record command appears in `evidence/`,
  `scripts/` or `docs/`. The only matches are prose stating that none was run
  (`docs/deployment.md:172`).

## Verdict
