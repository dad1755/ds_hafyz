## Verdict

**VERDICT: FAIL**

The sprint's hardening is real and well done — non-root, digest-pinned, immutable rootfs, no
capabilities, no host ports, bounded logs, and a restart that preserves data and artifact exactly.
The restore tool is genuinely paranoid and its three refusals all exit non-zero. The defect is the
seam between the two halves of the sprint: `scripts/backup.sh` stages its snapshot on the tmpfs that
S12 created and then tries to `docker cp` it out, which Docker cannot do, so the documented backup
procedure exits `1` on the stack this branch ships. Per `docs/runbook.md:136` that means no usable
backup exists, and the acceptance clause's round-trip is not reproducible from `ecbc8ef`.

Not merged. `s12/docker-hardening-recovery` stays unmerged; the defect is F-1 with its fix site at
`scripts/backup.sh:166` (or `:98`). A follow-up commit gets a re-verification by this verifier — this
record is not self-certification.
