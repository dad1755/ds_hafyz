## 5. Figure formatting — one gap

`ml/generate_eda.py` sets titles, axis labels and units for all six (`Accounts (count)`,
`Age (years)`, `Credit limit (NTD)`, `Default rate (%)`, `PAY_0 code (Sep 2005 repayment status)`,
`EDUCATION code`, `LMT = LIMIT_BAL; B1–B6 = BILL_AMT1–6; A1–A6 = PAY_AMT1–6 (NTD)`). Figures (a)–(e)
carry the source line, e.g. figure (d) reads verbatim:

```
Codes: –2 no consumption, –1 paid in full, 0 revolving, 1–8 months delay
Source: UCI Credit Card.csv — 30,000 accounts, Taiwan, Apr–Sep 2005
```

Figure (f), the heatmap, has **no source line** — the visual read of
`models/eda/06_correlation_heatmap.png` finds only the title, the tick labels, the `Pearson r`
colourbar and the abbreviation footnote. The cause is deliberate in code:
`ml/generate_eda.py:323` calls `finish(fig, out, len(df), source=False)`. Blueprint §9 SPRINT 3
requires "Format chart title, axes, source, units" for the set, and `docs/architecture.md` records
the source line as an intentional element of these figures, so this is a real omission rather than a
documented deviation — see F-1.

Sizing: five figures are 750 px wide (3.75 in at 200 dpi = 2× the 375 px viewport) and the heatmap
is 940 px; titles at 9.5 pt and labels at 8–8.5 pt render at ≥13 CSS px when halved to 375 px, so
the 375 px legibility claim holds for the plot area. The 5.6 pt source line lands near 8 CSS px —
legible but the smallest element on the figure.

## 7. Preprocessing contract

`docs/preprocessing_contract.md` (141 lines) was read in full. The five required items are present:

1. **Drop `ID` and the target** — §1: `ID` is "technical identifier — never a feature", the target is
   `default.payment.next.month`, and both are removed before anything is fitted.
2. **Stratified 80/20 with a fixed, recorded seed** — §2: `train_test_split(X, y, test_size=0.2,
   stratify=y, random_state=42)`, 24,000/6,000, `random_state=42` "written into `metrics.json`",
   test set touched once, model selection on training data only.
3. **`ColumnTransformer` fitted on train only** — §3 rule 1: one `Pipeline` per candidate with the
   transformer as first step, "the pipeline is fitted on `X_train`; the test set is only ever
   `transform`ed. `fit_transform` is never called on the full dataset", plus §6 check 2 asserting the
   scaler's `mean_` equals the train statistics.
4. **LogisticRegression scaled, trees unscaled, documented** — §3.1 table with the reason per
   estimator (`StandardScaler` for LR, `passthrough` for the tree and the forest, with "stated in
   the report, not smoothed over").
5. **Identical transform at inference through one saved `Pipeline`** — §3 rule 4 and §5:
   `models/best_pipeline.joblib` holds the fitted `ColumnTransformer` inside the pipeline, and
   serving calls `predict`/`predict_proba` on a 23-column frame in `FEATURES` order rather than
   re-implementing scaling.

It also fixes the threshold (0.5, in `models/model_manifest.json`), the always-class-0 baseline
comparison, the metric set, and the S4 artifact list and pre-claim checks. S4 can implement it
without inventing a decision. Two defects remain, neither of which changes an S4 decision:
a stale cross-reference (F-3) and an elided transformer column list (F-5, advisory).
