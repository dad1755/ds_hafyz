## §7 Staged ≠ deployed, and the pointer persists

After activating the staged 400-row subset the page's own verdict is:

```
page verdict — active dataset built the deployed model: False
deployed model dataset sha256: a0f0ab49d6326671d6cd83be5c88dcf18007025fe9a53ecd699119c871176ca1
```

i.e. the panel names the *seed* as the dataset behind the deployed model while the active pointer is version 2. That
is exactly the distinction §9 asks for, and it is stated in the affirmative and in the negative (the staged row says
"**not** active and the deployed model has not changed").

Persistence, across a new connection and a second startup:

```
-- restart: new connection to the same file --
active version after restart: 2 | sha256: 530b7202f526… | status: activated
rows with is_active = 1: 1
versions on disk: [(2, 'activated', True), (1, 'activated', False)]
pointer after a second startup: 2 (unchanged)
```

Exactly-one-active is enforced twice: inside the activation transaction and by a partial unique index
(`CREATE UNIQUE INDEX dataset_versions_one_active ON dataset_versions (is_active) WHERE is_active = 1`,
`src/db.py:122`), which a race cannot get around.

## §8 Admin only

`_admin` (the `require_role` wrapper, `src/data_manager.py`) is the **first executable statement** of every
privileged function: `stage_upload`, `activate_version`, `list_versions`, `active_version`, `list_rejections` and
`comparison`. `pages_datasets.render` calls its own `_guard` before rendering anything, and `_navigation` only offers
the entry to an admin — so the sidebar is convenience, not the boundary. The two functions with no guard are pure
helpers, not entry points: `aggregate_preview(payload: bytes)` summarises bytes the caller already holds and touches
no database, and `deployed_model_facts(models_dir)` reads the manifest from disk and changes nothing; both are only
reached from guarded paths. The suite's six parametrised
denials (`test_a_user_calling_a_dataset_function_is_denied_and_the_attempt_is_audited`) ran green in my §1 run, as did
`test_a_user_does_not_see_the_dataset_manager_entry`.
